# 机器人产业日报 · 国联民生研究所汽车组

面向客户的机器人产业日报产品（静态页面）：首屏是成品日报，固定结构为**今日主线 → 关键变化（近 3 天）→ 利好利空判断（按产业链环节）→ 受影响的中国上市公司 → 重点新闻 TOP 3–5 → 值得跟踪的信号 → 四板块详情**，下方保留国内新闻、海外新闻、机器人大厂、近期段子四个分类详表，支持搜索、时间与公司筛选、多方来源核对。

- 线上地址：<https://finn-tf.github.io/robot-news-board/>（仓库 <https://github.com/Finn-TF/robot-news-board>）
- 技术栈：纯静态 HTML + Python 标准库脚本，无需构建、无外部依赖。

## 日报是怎么生成的

每次抓取都会做同一套规则筛选，作为「候选池」：

1. **事件聚类**：用标题指纹（中文 2 字窗口 + 英文词，Jaccard ≥ 0.30）把同一事件的多家报道聚成一组；
2. **打分**：多家独立站点交叉印证 > 标题含量产/交付/订单/融资/上市/政策/财报等硬信息 > 发布时间最新 > 机器人本体与核心零部件词 > 头部机器人公司；
3. **去重**：同一标题反复出现、或同一家公司同一类事件（如「上市」）只保留一条；
4. **固定口径**：候选池最多 16 条，日报的重点新闻、跟踪信号**只能**从候选池里产生，候选池以外的内容不进入日报。

在此基础上：

- **三日窗口**：日报统计近 3 天（72 小时）的新闻，当日条目置顶，其余按发布时间倒序；三日内的新闻同时参与主线提炼、重点筛选、关键变化、利好利空与上市公司匹配。
- **规则模式（默认，无需 key）**：按打分排序取 3–5 条重点新闻；「影响判断」按事件类型套用固定口径（量产/融资/上市/政策/新品/组织调整），识别不了时明确写「暂无明确信号」；跟踪信号从量产、融资、上市、政策、财报、新品类条目中提取；利好利空按事件方向与产业链环节聚合，上市公司从已核验的白名单中按环节匹配。
- **DeepSeek 模式（配置 key 后启用）**：把候选池按编号交给模型，使用固定提示词与固定 JSON 结构输出「主线 + 关键变化 + 利好利空 + 受影响上市公司 + 重点新闻 + 信号」；脚本对输出做严格校验（编号必须来自候选池、不得重复、长度合规，上市公司 code+name 必须与白名单完全一致），不合格的条目直接丢弃并回落到规则结果，有效重点新闻不足 3 条则整体降级为规则模式。**链接一律取真实条目，不使用模型给出的链接。**
- 模型只能看到脚本给的候选条目，提示词明确禁止引入候选之外的公司、数字、订单、金额与来源，禁止目标价与投资评级。
- **正文只写结论**：固定提示词要求 mainline、关键变化、利好利空、重点新闻、信号只写事实与判断，**禁止出现条数、覆盖多少信息、通道数、来源数、交叉印证数量、覆盖率、抓取统计等元信息**；规则式降级模板同样不再输出统计口径，主线固定为「近三日机器人板块主线在「事件」，整体偏多/偏空，后续看……」的结论句。统计数字只放在报头与「数据口径」等独立位置。

日报写入 `data.json` 的 `report` 字段，页面直接渲染。

## 时间安排

| 任务 | 频率 | 北京时间 | GitHub cron（UTC） | 是否会调用 DeepSeek |
| --- | --- | --- | --- | --- |
| 常规抓取（`fetch.yml`） | 每 30 分钟 | 每小时 00 / 30 分（09:00 那轮跳过） | `*/30 * * * *` | 否，只更新列表与规则式日报 |
| 早间抓取（`morning.yml`） | 每天一次 | 08:50 | `50 0 * * *` | 否，只刷新数据 |
| 正式日报（`daily.yml`） | 每天一次 | 09:00 | `0 1 * * *` | 是（有 key 时），失败自动降级 |

- GitHub Actions 的 cron **只认 UTC**；北京时间 08:50 = UTC 00:50，09:00 = UTC 01:00。
- **08:50 早间抓取**：刷新全部网页/检索通道、公众号白名单和「汽车琰究」文章栏（`wechat_articles.json`），不调用模型，只把最新数据写回 `data.json` 与当日归档。
- **09:00 正式日报**：`--daily` 内部会**重新执行一次完整抓取**，不是读 08:50 的结果；因此 08:50 延迟或没跑完也不会用旧数据。生成后还有一步「数据新鲜度校验」，超过 30 分钟直接停止发布。
- **顺序保障**：三条 workflow 共用 `concurrency: group: pages`（`cancel-in-progress: false`），后到的任务排队等待前一个结束，不会并发写 `data.json`；`fetch.yml` 在 UTC 01:00-01:14 主动跳过，避免和日报抢队列。
- 30 分钟的常规抓取**不会**调用 DeepSeek；当天已有 DeepSeek 日报时保持不覆盖，只刷新下方列表。
- 若 9:00 那次 DeepSeek 调用失败（超时、限流、key 无效、JSON 解析失败等），自动用规则式生成当日日报并照常归档，不会出现「当天没有日报」；失败原因写入 `report.llm.error` 与 Actions 日志（不含 key）。

## 归档机制

- 每期日报完整快照写到 `archive/YYYY-MM-DD.json`，索引写到 `archive/index.json`；
- 同一日期重跑只覆盖当日快照（当天日报滚动更新），**其他日期永不改写**，重新抓取不会覆盖历史日报；
- 期号按归档天数递增，同一天沿用同一期号；
- 页面右上角「往期」下拉可切换日期，默认最新一期；用 `?date=YYYY-MM-DD` 可直接分享某一期；
- 归档目录会随 Pages 一起发布（`deploy.yml` / `daily.yml` / `fetch.yml` 都会复制 `archive/`）；
- 本地双击打开（`file://`）时，浏览器无法读取 `archive/` 目录，只能看最新一期；要回看往期请用本地服务或线上地址。

## 接入 DeepSeek（用户自行配置 key）

### 第一步：先在本地确认 key 可用（推荐）

key 还没配到仓库前，可以先在本机自检，不写任何文件、不打印完整 key：

```powershell
# PowerShell（只对当前终端生效，关闭窗口即失效）
$env:DEEPSEEK_API_KEY = "sk-..."   # 换成你自己的 key，不要写进 config.json
python check_llm.py
```

- 成功会打印：`[成功] DeepSeek 连通，模型有正常返回。`，并显示模型回显与 token 用量；
- 失败会直接翻译原因：401 表示 key 无效/复制不完整，402 表示余额不足，404 表示接口或模型名不对，429 表示限流，超时表示网络/代理问题；
- 退出码：0 成功、1 未设置 key、2 调用失败；脚本不会把 key 写入任何文件或日志。

key 在 DeepSeek 开放平台 <https://platform.deepseek.com> 的 **API keys** 页面创建，**只在创建时显示一次**，关掉页面就看不到了，请当场复制。

### 第二步：把 key 加到 GitHub 仓库（图文步骤）

1. 打开仓库 <https://github.com/Finn-TF/robot-news-board>；
2. 点右上角 **Settings**（仓库设置，不是个人账号设置）；
3. 左侧栏找到 **Secrets and variables** → 点下面的 **Actions**；
4. 页面分两块：**Environment secrets** 和 **Repository secrets**。**只用下面那块 Repository secrets**，Environment secrets 不用管；
5. 点右下角绿色按钮 **New repository secret**；
6. **Name** 填：`DEEPSEEK_API_KEY`（全大写、下划线，前后不要有空格）；
7. **Secret** 粘贴你的 key（粘贴后输入框不会显示明文，这是正常的）；
8. 点 **Add secret**；
9. 回到列表，看到 `DEEPSEEK_API_KEY` 一行、右侧显示更新时间，就说明保存成功。

注意事项：

- 保存后**再也看不到 key 原文**，这是 GitHub 的正常设计；忘了只能删除重建；
- 如果页面显示 “This repository has no secrets.”，说明还没保存成功，重新走第 5–8 步；
- 名称必须完全一致 `DEEPSEEK_API_KEY`，写成 `DEEPSEEK-KEY`、`DEEPSEEK_API_KEY `（带空格）都不会生效；
- 不要用 Environment secrets 代替，本项目的 workflow 读取的是仓库级 secret。

### 第三步：确认配置并触发

`config.json` 中已预设：

```json
"llm": {
  "enabled": true,
  "provider": "deepseek",
  "model": "deepseek-chat",
  "base_url": "https://api.deepseek.com",
  "api_key_env": "DEEPSEEK_API_KEY",
  "max_tokens": 8192,
  "temperature": 0.3,
  "timeout": 60
}
```

- `enabled` 已为 `true`：secret 一旦配好，下一次每天 9:00（北京）的日报任务会自动使用 DeepSeek，**不需要改代码或再推一次**；
- 想立刻验证：Actions → **每日 9 点生成日报** → **Run workflow**；
- 看运行日志里的 `日报：DeepSeek（deepseek-chat）生成成功` 即成功；若显示 `DeepSeek 失败，降级为规则式（原因）`，按括号里的原因处理（见上面 401/402/404 的说明）；
- 成功后页面报头右侧会显示「DeepSeek 辅助生成 · deepseek-chat」，否则显示「规则口径」。

## 本地运行

**直接双击 `index.html`** 即可打开（页面读取同目录 `data.js` 的内嵌数据，含最新一期与归档索引）。

也可以用本地服务打开（能读到 `data.json` 并切换往期）：

```
python -m http.server 8765
# 浏览器访问 http://127.0.0.1:8765/index.html
```

常用命令：

```
python fetch_news.py                 # 常规抓取：更新列表 + 规则式日报 + 当日归档
python fetch_news.py --daily         # 正式日报：允许调用 DeepSeek，强制归档当日一期
python fetch_news.py --no-translate  # 不翻译，英文保留原文
python fetch_news.py --max 80        # 每板块最多条数（默认 60）
python fetch_news.py --sync-only     # 不联网，仅用当前 data.json 重新生成 data.js
python fetch_news.py --daemon        # 常驻定时抓取（间隔读 config.json，默认 30 分钟）
```

`config.json` 字段：

```json
{
  "interval_minutes": 30,
  "retries": 2,
  "max": 60,
  "per_source": 16,
  "translate": true,
  "llm": { "...": "见上" }
}
```

`interval_minutes` 常驻模式抓取间隔（分钟，默认 30）；`retries` 单轮失败重试次数；`max` 每板块最多条数；`per_source` 单通道每板块条数上限；`translate` 是否把英文标题/摘要翻成中文。

## 页面结构

固定顺序，不随日期漂移：

1. **报头**：`机器人产业日报 · 第 N 期`、日期与星期、国联民生研究所汽车组、数据更新时间、往期下拉、通道状态；
2. **今日主线**：一句话概括近三日机器人板块核心变化，并列出窗口条数、当日条数、多家印证条数、媒体数、通道成功率；
3. **关键变化**：近 3 天的关键事件，当日条目置顶并标「今天」，其余按日期倒序，每条带日期、来源与原文链接；
4. **利好利空判断**：先给整体方向（整体偏利好 / 整体偏利空 / 多空交织中性 / 暂无方向性信号），再按产业链环节（本体、减速器、伺服/电机、丝杠、灵巧手、执行器、传感器、控制器、机器视觉、软件/具身智能、结构件、热管理、应用场景）给出方向与「事件 → 环节 → 订单/成本/估值」的传导逻辑；
5. **受影响的中国上市公司**：A 股中文全称 + 股票代码、所属环节、方向、影响程度、确定性、受影响原因；公司只来自已核验的白名单，白名单外的公司不列；
6. **重点新闻 TOP 3–5**：大卡片置顶，第一条高亮；每条含「事件 → 摘要 → 影响判断 → 来源链接」，标注「多家印证 · N 家 / 单一来源」；
7. **值得跟踪的信号**：量产/交付、订单、融资、上市、政策等前瞻信息，每条带日期与来源；
8. **分类详表**：国内新闻 / 海外新闻 / 机器人大厂 / 近期段子，保留原有 Tab、搜索、时间与公司筛选、核对徽标；
9. **页脚**：免责声明（通用占位，可替换为机构合规模板）、日报结构说明、数据口径、抓取状态与来源清单、公众号白名单。

### 微信公众号白名单

`wechat_sources.json` 是可维护的白名单配置，字段：`name`（号名称）、`type`（公司/行业/新闻/智库/券商）、`certified`（是否已微信认证）、`reason`（收录理由）、`status`（active/manual）、`error`（原因）。

- **只收权威、官方且已认证的号**：公司官方号、行业号、主流财经/科技新闻号、智库/研究机构/协会/展会主办方号；非认证号、个人号、营销号、内容农场、搬运号一律不收。
- **券商类只收录国联民生证券一家**：白名单中券商类型只允许「汽车琰究」（国联民生证券汽车组官方号，固定信源）；脚本额外做了硬校验，即使配置被误改，其他券商号也不会被抓取。
- **抓取方式**：通过搜狗微信检索按号名抓取近期文章；如遇反爬验证、无更新或认证状态未核验，会在 `data.json.wechat.accounts` 与页脚「抓取状态」中标记 `fail / empty / manual` 及原因，**不用其他来源顶替、不伪造该号内容**。
- **引用规范**：公众号条目入库后，来源显示为「公众号·号名」，并带发布时间与可打开的原文入口。

### 「汽车琰究」文章栏（近期段子板块内）

页面「近期段子」板块顶部固定展示「汽车琰究」最新文章（标题、发布日期、作者、摘要、原文链接），段子内容继续保留在下方。该栏目是**固定信源**：即使某次一篇都没抓到，栏目和「汽车琰究」这个名字也不会被删除，并显示最近一次成功抓取时间与失败原因。

配置在 `wechat_articles.json`：

| 字段 | 作用 |
| --- | --- |
| `links` | 手动维护的文章直链数组。从公众号文章页复制 `https://mp.weixin.qq.com/s/...` 贴进去即可 |
| `auto_discover` | 是否尝试解析合集/专辑页 |
| `albums[]` | 合集参数数组（`album_id` / `label` / `count`）；只覆盖被合集收录的文章，**不能保证覆盖全号** |
| `max_items` | 栏目展示条数（默认 7）；按发布时间倒序，超出部分从旧到新丢弃 |

以后加新文章：把链接追加到 `links` → 跑一次 `python fetch_news.py`（或等下一次 8:50 / 30 分钟抓取）→ 提交推送，页面自动出现。抓取失败、链接失效、反爬都会在栏目内标注原因，不使用其他券商或公众号内容顶替。

**筛选口径与能力边界**：栏目按发布时间倒序取**最新 `max_items` 篇（默认 7 篇）**，不限日期；日期跨度较大时每篇照常显示发布日期，页头同时显示「日期跨度 X ~ Y」，避免把旧文误认为近一周内容。实测各条自动发现路径：

| 路径 | 实测结果 |
| --- | --- |
| 搜狗微信按号检索（桌面 UA） | 302 跳转到 `antispider/?antip=wx_sh2` 验证码页，无结果块 |
| 搜狗微信按号检索（移动 UA） | 能解析出结果块和公众号名，但该号索引停在 2020-2024 年，**没有近一周文章**；加 `tsn` 时间筛选后返回 3813B 空壳页 |
| 公众号历史页 `profile_ext` | 返回微信验证页（需客户端登录/令牌），无法直接抓 |
| 合集总目录 `getalbumlist` | 返回 `{"ret":-3,"errmsg":"no session"}`，需要登录态 |
| 文章页合集参数 | 只能解析到该文章所属的单个合集；从合集文章页继续挖掘，共找到 2 个合集（小鹏系列、2024 汽车出海系列），均无近一周新文章 |
| 文章页内链 | 仅有一条 2020 年的“名誉保护投诉指引”，非该号文章，无法滚雪球 |
| 手动链接清单 | **可用**，支持一次贴多篇，按发布时间倒序进入最新 7 篇 |

因此，若要保证「近一周全部文章」，需要在 `links` 里补齐该周文章直链，或接入 RSS 中转（Wechat2RSS 私有部署需付费订阅、自建服务器并完成微信/微信读书授权；其免费公共清单不含「汽车琰究」。RSSHub 的公众号路由依赖第三方服务，自身不能直接抓）。

### 段子内容维护（近期段子板块下方）

段子**不自动抓取、不写入任何示例占位内容**，只来自用户手动提供：

- 存放位置：`data.json` → `boards.jokes.items`（数组）；
- 单条字段：`title`（必填，段子正文或标题）、`summary`（可选，补充说明）、`source`（可选，如「手动录入」）、`published`（可选，ISO 时间，如 `2026-11-19T10:00:00+08:00`，用于按时间倒序）；
- 写入后运行 `python fetch_news.py --sync-only`（不联网，只把 `data.json` 重新生成到 `data.js`），再提交推送；或等下一次 8:50 / 30 分钟抓取，脚本会保留已有段子原样不动；
- 一条段子都没有时，板块标题、汽车琰究栏目和板块结构都保留，下方显示「暂无段子，可随时补充」，不会留大片空白，也不会出现假内容。

## 上市公司白名单

`fetch_news.py` 中的 `COMPANY_CHAIN` 是受影响 A 股公司白名单，包含中文全称、股票代码、所属环节、主营与确定性。代码已通过东方财富行情接口逐个核验，避免凭印象写代码或编造不存在的公司。

- DeepSeek 只能从该白名单选公司，且 `code + name` 必须完全一致，否则该条直接丢弃；
- 规则模式按新闻命中的产业链环节匹配，每个环节最多取 3 家，最多 8 家；
- 拿不准的环节宁可不列，页面不会展示白名单之外的公司。

## 信息核对

每条资讯底部列出该事件的来源清单：同一事件在 **≥2 家独立站点（按域名判定）** 出现时标绿色「✓ 已核」；只有 1 家时标「单一来源」。

- 来源名可点击，直接打开对应原文；
- 核对结果只来自本轮真实抓到的条目，抓不到第二家就如实标单一来源，不会编造「已核」；
- `data.json` 中每条记录带 `verify` 字段（`level: cross/single`、`count`、`sources[]`）。

## 已知限制

1. **微信公众号抓取不稳定**：通过搜狗微信检索抓取会触发反爬验证或返回空结果；白名单中的号若抓取失败、无更新或认证状态未核验，会在 `data.json.wechat.accounts` 与页脚「抓取状态」中如实标记，不用其他来源顶替、不伪造内容。公众号文章的实际可抓取性取决于微信/搜狗策略，可能需要人工补充。
2. **Google 新闻检索未使用**：其 RSS 链接是 `news.google.com` 跳转地址，不如 Bing 的原文直链可靠。
3. **部分站点反爬**：如 36氪、虎嗅、机器之心、界面、Robotics 24/7、Meta AI Blog 等可能 403/404/限流，脚本如实记录失败，不造假。
4. **翻译**：英文条目的中文标题/摘要调用 Google 翻译公开接口，机翻可能有偏差，页面保留英文原标题便于核对；接口不可用时保留英文原文。
5. **信息核对的边界**：只做「多家独立站点是否报道同一事件」的交叉印证，不等于事实核查；转载、通稿会被当作多来源，标题聚类也可能漏配，判断真伪仍需点开原文。
6. **规则式影响判断**：无 key 时「影响判断」是按事件类型生成的通用口径，不是针对具体公司的深度分析，页面会标明「规则口径」。
